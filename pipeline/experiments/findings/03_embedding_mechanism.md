# 结论 03: 嵌入机制与成本

## 先分清两个"窗口"

本轮出现了两个都叫"窗口"的参数, 含义完全不同:

```text
边界窗口  window_chars=200     切点可以移动的范围(相当于 overlap)
                               只影响【切在哪】, 不影响嵌入成本

嵌入窗口  radius=1             拼进嵌入的上下文范围(前后各 1 句)
                               直接决定【嵌入成本】—— 每位置嵌 3 句而不是 1 句
```

**本轮的结论:**

```text
成本差异(结论 1)    只与【嵌入窗口】有关, 与【边界窗口】无关
效果数据(结论 3)    是在【边界窗口 = 200】这一设置下测的
```

**所以下面这组成本倍数(2.91x / 2.14x / 4.05x), 不会因为把边界窗口从 200 调到 400 而改变。**

## 实验条件

两组实验合并:

```text
实验 A  嵌入机制对边界识别能力的影响
        数据  experiments/08_embedding_mechanism_compare.txt
        脚本  embedding_mechanism_compare.py

实验 B  三种嵌入配置的成本与分块效果
        数据  experiments/09_embedding_config_compare.txt
        脚本  embedding_config_compare.py
```

共用条件:

```text
语料     corpus/redhat_p1-20.md (274 句 / 17123 字)
模型     阿里云百炼 qwen3-vl-embedding (1024 维)
参数     实验 B 的切点判定用 max_chars=800, window_chars=200
```

## 结论 1: 成本主要差在"嵌窗口"还是"嵌单句"

```text
配置                     调用次数   输入字符数    相对基准
────────────────────────────────────────────────────────
A. 单句嵌入                 274      17123       1.00x
B. 窗口嵌入(radius=1)       274      49760       2.91x
C. 单句 + metadata 前缀      274      36709       2.14x
D. 窗口 + metadata          274      69346       4.05x

metadata 前缀平均长度: 69.5 字/句    (正文平均 62.5 字/句)
```

**两个量化结论:**

- **窗口嵌入的成本是单句的 2.91 倍** —— 与"边界窗口多大"无关, 是嵌入机制本身决定的(每个位置嵌 3 句而不是 1 句)
- **把 metadata 拼进嵌入会让成本翻倍(1.00x → 2.14x)** —— 因为示例里的 metadata 前缀比正文还长

**metadata 的写法直接决定成本:**

```text
写法                                      平均长度   相对基准
file: xxx.pdf | page: N | section: xxx      69.5 字     2.14x
"p12"                                        约 4 字     1.06x
不加                                         0          1.00x
```

## 结论 2: 哪种机制更能识别语义边界

用 Markdown 标题边界做**弱标注**(52 个断点 / 273 个位置), 算 AUC:

```text
机制         断点均值   非断点均值    差距      AUC
──────────────────────────────────────────────────────
单句嵌入     0.3905     0.3543      +0.0362   0.5934
窗口嵌入     0.0780     0.1010      -0.0230   0.3479
```

**AUC 0.5 = 随机。单句 0.59(略好), 窗口 0.35(比随机还差)。**

### 窗口嵌入为什么会低于随机

**它的距离存在位置错位:**

```text
窗口 i   = [S(i-1), S(i),   S(i+1)]
窗口 i+1 = [         S(i),   S(i+1), S(i+2)]
                    ↑ 中间两句完全相同

两个窗口的差异 = 窗口 i 独有的 S(i-1)  vs  窗口 i+1 独有的 S(i+2)
```

**所以 `d(窗口 i, 窗口 i+1)` 衡量的不是"S(i) 和 S(i+1) 的差异", 而是"S(i-1) 和 S(i+2) 的差异"—— 整整错开两格。**

如果 S(i-1) 和 S(i+2) 恰好都在讲同一个大主题(标题前后很常见), 距离就会反常地小。

**这解释了另一个实验里的现象**: `06_sentence_window_retrieval.txt` 中, 窗口嵌入做检索时**每次都偏一格** —— 不是"模糊", 是系统性的位置偏移。

## 结论 3: 分块效果对比

在 `max_chars=800, window_chars=200` 下:

```text
配置                     块数    min    均值    切点均距
─────────────────────────────────────────────────
A. 单句嵌入               23     357    744    0.4495
B. 窗口嵌入(radius=1)     23     281    744    0.1448
C. 单句 + metadata        22     575    778    0.2783
```

**三种配置的距离尺度都不同, 切点均距不能横向比大小:**

```text
A  0.4495    单句嵌入的标准尺度
B  0.1448    窗口嵌入 —— 相邻窗口共享 2/3, 距离被压到约 1/3
C  0.2783    加 metadata —— 共同前缀把向量推向同一方向, 距离被压缩
```

**块数基本一致(22~23)**, 说明三种机制找到的切点数量相当。

**单句嵌入的实际切点位置(前 5 块):**

```text
块2→块3  距离 0.3874   下一块从 "它由两种主要技术组成..."
块3→块4  距离 0.5054   下一块从 "## 1.2. HAPOXY ..."      ← 新章节
块4→块5  距离 0.4605   下一块从 "## 注意 红帽不支持..."     ← 新小节
```

**两个切点正好落在 Markdown 标题边界上** —— 单句嵌入确实识别出了结构边界。

## 适用边界

### ⚠️ 这一节最重要

**关于成本(结论 1):**

```text
✅ 与"边界窗口多大"无关
   "嵌窗口 = 3 倍成本" 是每位置嵌 3 句 vs 1 句决定的, 换窗口宽度不变
   改窗口宽度只影响切点能挪多远, 不改变嵌入次数

✅ 可推广到其他语料
   "metadata 前缀越长成本越高" 是线性关系, 比例与语料无关

❓ 不可推   具体的 2.14x
   取决于 metadata 写多长 —— 换个字段设计比例就变
```

**关于机制对比(结论 2):**

```text
✅ 数学上可推导   位置错位是窗口嵌入的结构性性质, 与语料无关
                d(窗口i, 窗口i+1) 差的是 S(i-1) 和 S(i+2)

⚠️ 标注不可靠     用 Markdown 标题当"真断点"是【弱标注】
                 - 标题边界 ≠ 语义边界(很多标题下内容连续)
                 - 标题句不纯(标题无句末标点, 和正文粘在一起)
                 - 复核只用一级标题时只有 5 个正样本, 方向完全反了,
                   说明样本量不足, 复核无效

❓ 不可推   AUC 0.5934 / 0.3479 的具体数值
          换个更好的标注, 差距可能变化
```

**关于分块效果(结论 3):**

```text
⚠️ 参数特定   块数/min/切点均距是在 window_chars=200 下测的
              改窗口大小, 这三个数字都会变(见结论 02)

❓ 不可推    只有一份语料
```

### 明确未解决的问题

```text
三种配置【哪个分块效果更好】—— 这个问题没有被本实验回答

原因: 切点均距是【代理指标】, 衡量"切点是否落在语义跳变处",
      不代表检索效果。而且三种机制尺度不同, 无法直接比较。

要回答它, 必须: 建索引 -> 跑检索 -> 用 recall@k / MRR 衡量
      这一步尚未做, 因为没有评估集
```

## 可落地的建议

```text
分块阶段算切点距离时:

推荐  单句嵌入 (1.00x)
      理由: 成本是窗口嵌入的 1/3; 距离没有位置错位问题;
            实测切点落在标题边界上

不推荐 metadata 进分块阶段的嵌入 (2.14x)
      理由: metadata 对"找切点"没帮助, 它的价值在检索阶段的过滤
            这也符合 OpenAI 的做法 —— attributes 只用于 filters, 不进嵌入

不推荐 窗口嵌入 (2.91x)
      理由: 成本 3 倍, 且距离存在结构性位置错位
```
