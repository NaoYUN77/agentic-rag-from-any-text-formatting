# 结论 02: 边界窗口宽度的影响

## 实验条件

```text
语料     corpus/redhat_p1-20.md (274 句 / 17123 字)
模型     阿里云百炼 qwen3-vl-embedding (1024 维)
嵌入机制 【单句嵌入】 —— 每句一个向量, 不拼窗口, 不用 metadata
方法     固定长度粗切(max_chars=800) + 在边界前 window_chars 范围内挑语义断点
数据     experiments/05_window_sweep.txt
```

**两种机制的距离尺度不可比** —— 这里的"相对全局"以单句嵌入的全局均值 0.3612 为分母。

## 结论

```text
窗口   块数   字数 min/均值/max        切点均值距离   相对全局
─────────────────────────────────────────────────────────────
   0     21     438 /   815 /  2138      0.3628        1.00x   ← 纯固定长度
 100     22     214 /   778 /  2138      0.4319        1.20x
 200     23     357 /   744 /  2138      0.4495        1.24x
 300     23     357 /   744 /  2138      0.4624        1.28x
 400     24     431 /   713 /  2138      0.4881        1.35x
 600     28     171 /   612 /  2138      0.5221        1.45x
```

**四个发现:**

1. **窗口=0 时切点距离 0.3628 几乎等于全局均值 0.3612** —— 纯固定长度的切点在语义上是**随机的**（随机位置的平均距离期望就是全局均值，这是数学必然）
2. **窗口越大，切点质量单调提升** —— 0.3628 → 0.5221，单调
3. **代价同步上升** —— 块数 21→28 (+33%)，最小块 438→171
4. **边际收益递减** —— 0→100 提升 0.20x，400→600 只多 0.10x 却让最小块从 431 掉到 171

**推荐区间: 窗口 = 块大小的 1/4 ~ 1/2。**

## 适用边界

```text
✅ 可推广   "窗口=0 时切点随机" —— 这是数学必然, 与语料无关
✅ 可推广   "窗口越大切点质量越高" —— 单调性在逻辑上成立
✅ 可推广   "窗口 = 1/4 ~ 1/2 块大小" —— OpenAI 的 50% 默认值落在这个区间
❓ 不可推   具体倍数(1.20x / 1.35x)只对这份语料成立
❓ 不可推   200 和 300 之间的差异(1.24 vs 1.28) —— 太小, 不该当结论
```

**最大局限: 只有一份语料（274 句、一份 PDF 技术手册）。** 换文档类型（法律、小说、代码）结论可能不同。
